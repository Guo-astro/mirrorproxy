# CodeQL remediation: 2026-10-22

The baseline main commit `0f900fa` had 30 open Rust alerts: 26 hard-coded
credential findings in tests (#73–98), three non-HTTPS test targets (#70–72),
and one weak-sensitive-data-hashing finding (#57).

## Changes and security boundaries

- Authentication fixtures now generate independent credentials at runtime and
  reuse them only within their test. Password-policy tests retain random short
  and username-equality cases and exercise every entry of the existing common
  password denylist, including case normalization.
- The plain HTTP proxy test uses a loopback-only target and verifies the exact
  generated Basic credential. SOCKS tests tunnel to a real local TLS origin
  with an explicitly trusted, freshly generated certificate. SOCKS5h still
  asserts a domain-name request (remote DNS), credentials, and port 443;
  SOCKS5 still asserts an IP-address request (local DNS) and the requested port.
  Successful `/from-socks` responses verify the tunneled application request.
- Alert #57 traces the return of `password_work` / `verify_password_async`
  through a successful login to a **new random session token**, not password
  bytes. CodeQL's Rust sensitive-data source heuristic identifies calls by
  function name without checking their return type. Name the executor
  `run_argon2_task` and boolean checks `argon2_matches[_async]` to describe
  their actual results. Keep the bounded executor, Argon2 password hashing,
  independent random session tokens, and existing SHA-256 token lookup format.
  See the official [Rust sensitive-data heuristic](https://github.com/github/codeql/blob/main/rust/ql/lib/codeql/rust/security/SensitiveData.qll).
- Additional regressions verify independent Argon2 salts, correct and incorrect
  credentials, malformed stored hashes, and independent 48-character login
  tokens whose hashes (rather than plaintext) are stored in SQLite.

No rule is disabled, path excluded, alert dismissed, authentication check
weakened, dependency changed, or database format migrated by this fix. No
production replacement should happen before the exact fix commit has passed
CI and CodeQL and the open-alert state has been checked separately.

so protocol tests must run with local socket permission. A restricted run is
not evidence of a protocol regression.
